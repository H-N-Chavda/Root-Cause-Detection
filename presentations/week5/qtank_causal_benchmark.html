The ground truth

Every arrow on the previous slide is one term in the four mass-balance equations of the simulator

Level hᵢ in cm, pump voltages v₁, v₂ in V, disturbance flow d, g = 981 cm/s². Aᵢ tank area, aᵢ outlet area, γ valve split, kᵢ pump gain.

ḣ₁ = −(a₁/A₁)√(2g h₁) + (a₃/A₁)√(2g h₃) + (γ₁k₁/A₁) v₁

ḣ₂ = −(a₂/A₂)√(2g h₂) + (a₄/A₂)√(2g h₄) + (γ₂k₂/A₂) v₂

ḣ₃ = −(a₃/A₃)√(2g h₃) + ((1−γ₂)k₂/A₃) v₂ + (γ₃/A₃) d

ḣ₄ = −(a₄/A₄)√(2g h₄) + ((1−γ₁)k₁/A₄) v₁ + ((1−γ₃)/A₄) d

Blue terms are the four pump arrows. Each pump appears in two equations because the valve splits its flow by γ.

Orange terms are the two drainage arrows: the upper tank's outflow √(2g h₃) is an inflow to the lower tank.

Grey terms are the disturbance arrows, split γ₃ = 0.4 between the upper tanks.

The first term in each row is the tank's own outflow: the self-dependence hᵢ(t−1) → hᵢ(t) that every time-series method must handle.

Parameters: A₁,A₃ = 28 cm², A₂,A₄ = 32 cm², a₁,a₃ = 0.071, a₂,a₄ = 0.057 cm², k₁ = 3.14, k₂ = 3.29, γ₁ = 0.43, γ₂ = 0.34. Measurement and input noise σ = 0.05.

The data

Inputs are square waves and strongly non-Gaussian; the tank levels are smooth, near-Gaussian and highly autocorrelated

Measured on the generated data before any algorithm ran. These properties decide which method assumptions hold.

Shape of the distribution

−2.0

excess kurtosis of v₁, v₂, d: a two-level square wave, as far from Gaussian as it gets (Jarque–Bera p ≈ 10⁻¹⁰⁵)

Levels h₁–h₄: Jarque–Bera p between 0.008 and 0.35, close to Gaussian because each tank low-pass filters its inputs

Memory

0.93–0.99

lag-1 autocorrelation of the levels; inputs 0.83–0.90

Each sample is almost a copy of the previous one. A method that ignores this sees spurious links everywhere.

Stationarity and sampling

p < 10⁻⁴

augmented Dickey–Fuller test on all 7 columns: no unit root, no trend

Ts = 5 s, 4 h, 2880 rows per dataset, 600 s burn-in discarded. Pumps switch every 30 s, disturbance every 50 s.

Consequence: partial correlation (linear) is defensible for the levels; the non-Gaussian pump signals are what VAR-LiNGAM's direction rule needs, and they are exactly the variables that are inputs, not tanks.

5

How we score

Every algorithm hands back a graph; we count how many of the 8 true arrows it found, missed, flipped or invented

Edge outcomes

Found: true arrow, right direction (TP)

Missed: true arrow not reported (FN)

Reversed: true pair, wrong direction

Invented: reported arrow with no pipe behind it (FP)

Lagged edges are collapsed to one arrow per pair before scoring. Self-loops are counted separately.

Two scores, read together

precision = TP / (TP + FP + reversed)

recall = TP / 8

F1 = 2 · precision · recall / (precision + recall)

SHD = missed + invented + reversed: the number of single-edge edits to reach the true graph. Lower is better; 0 is perfect.

F1 already punishes invented edges through precision; SHD adds a raw count that does not saturate and treats a flip as one edit, not two.

Shared settings, main run

Rows: every 3rd sample, 960 rows per dataset at Ts = 15 s

Window: τₘₐₓ = 20 steps = 300 s, about 3 time constants of the slowest tank

Test: partial correlation, α = 0.01

VAR-LiNGAM only: 20 lags, 100 bootstrap resamples, keep edge if in ≥ 90. PC and PCMCI+ use no bootstrap; one test per edge at α = 0.01

The same three methods were also run on all 2880 rows at 5 s (100 s window); that comparison is on its own slide.

Source: datasets/score_runs.py; results/qtank/run-parcorr-tau20-s3/run_summary.json (stride 3, re-run 28 Sep 2026)

The methods

Three ways of asking "does A drive B?", each with a different blind spot

PC

Removes a link whenever two signals become unrelated once you control for the others.

Built for snapshots, not time series. We ran it twice: with no time window, and with the same 20-step window as the others.

Blind spot: no correction for signals that mostly predict themselves

PCMCI+

PC redesigned for time series. Tests each link at every lag in the window and corrects for autocorrelation.

The method the literature recommends for slow, autocorrelated process data. Our pre-registered favourite.

Blind spot: linear test only, in this run

VAR-LiNGAM

Fits a linear forecasting model, then uses the shape of the noise (non-Gaussian) to decide which way each link points.

Keeps a link only if it survives 90 of 100 bootstrap resamples.

Blind spot: direction is unreliable where the noise is Gaussian (the tank levels)

Source: src/causal_bench/algorithms/pc.py, pcmci_plus.py, var_lingam.py; docs/QTP_EXPECTATIONS.md

8

Method 1 of 3 · PC

PC deletes a link whenever a conditional-independence test says two variables are unrelated given some others

Step 1 · Skeleton

Start fully connected. For every pair (X, Y) and conditioning set S of growing size, remove the edge if

X ⊥ Y | S  ⇔  ρ(X, Y | S) = 0

ρ(X, Y | S) is the partial correlation: regress X and Y on S, correlate the residuals. Tested with Fisher's z:

z = ½ ln[(1+ρ)/(1−ρ)] · √(n − |S| − 3)  ~  N(0,1)

Edge removed if the two-sided p-value exceeds α = 0.01. The S that separated them is remembered.

Step 2 · Orientation

For every path X – Z – Y with X and Y not adjacent: if Z was not in the set that separated X and Y, orient as a collider

X → Z ← Y

Then propagate with Meek's rules (no new colliders, no cycles). Edges neither rule reaches stay undirected.

How we ran it here

No window: the 7 variables at the same time step only. 20-step window: the lagged copies Xₜ₋₁ … Xₜ₋₂₀ are added as extra variables and time order is used to forbid future → past. No correction for autocorrelation in either case.

Source: src/causal_bench/algorithms/pc.py (tigramite PC with ParCorr); Spirtes, Glymour & Scheines, Causation, Prediction and Search

9

Method 2 of 3 · PCMCI+

PCMCI+ runs the same tests on time-lagged variables, but conditions on both variables' own past so autocorrelation cannot fake a link

Step 1 · Lagged parent search (PC₁)

For each target Xʲₜ, candidates are every Xⁱₜ₋τ with 1 ≤ τ ≤ τₘₐₓ = 20. Iteratively drop a candidate when

Xⁱₜ₋τ ⊥ Xʲₜ  |  S,  S ⊆ strongest remaining candidates

Output: an estimated parent set P̂(Xʲₜ) for every variable. Contemporaneous links (τ = 0) are handled in the same loop with S drawn from both lagged and same-time parents.

Step 2 · Momentary conditional independence (MCI)

Every surviving link is re-tested with both parent sets in the condition:

Xⁱₜ₋τ ⊥ Xʲₜ  |  P̂(Xʲₜ) \ {Xⁱₜ₋τ},  P̂(Xⁱₜ₋τ)

Conditioning on P̂(Xⁱₜ₋τ) removes the cause's own memory; conditioning on P̂(Xʲₜ) removes the effect's. What is left is the momentary effect of i on j, and its false-positive rate is controlled at α even under strong autocorrelation.

Same-time links are oriented by collider rules; lagged links by time order. Same ParCorr test, α = 0.01.

In practice the 7 columns are widened in memory to 7 + 7 × 20 = 147 columns (each variable at t, t−1 … t−20); the first 20 rows are dropped. Every (i, j, τ) triple is tested, about 1000 pairs plus conditioning sets, each a small regression. Both datasets finished in 1.5 s.

Source: src/causal_bench/algorithms/pcmci_plus.py (tigramite PCMCIplus); Runge, UAI 2020

10

Method 3 of 3 · VAR-LiNGAM

VAR-LiNGAM fits a linear forecasting model, then uses the non-Gaussian shape of the residuals to decide which way each same-time link points

The model

xₜ = B₀ xₜ + Στ=1..p Bτ xₜ₋τ + eₜ

B₀ is the same-time graph (must be acyclic), Bτ the lagged effects, eₜ independent and non-Gaussian. p = 20 here.

Step 1 · Ordinary VAR

xₜ = Σ Mτ xₜ₋τ + nₜ  (least squares)

The residuals nₜ contain all the same-time structure, mixed together.

Step 2 · LiNGAM on the residuals

nₜ = B₀ nₜ + eₜ

DirectLiNGAM finds the causal order: the variable whose regression residual is most independent of the others is the root; regress it out, repeat. Independence, not correlation, is what breaks the symmetry, and it needs non-Gaussian eₜ. With Gaussian noise every order fits equally well.

Step 3 · Recover the lagged effects

Bτ = (I − B₀) Mτ

Bootstrap: refit on 100 resampled series; keep an edge only if non-zero in 90 of them. That is where the 134 s goes.

Source: src/causal_bench/algorithms/var_lingam.py (lingam.VARLiNGAM); Hyvärinen et al., JMLR 2010; Shimizu et al., JMLR 2011

Shortcuts of a real path: v2→h1 three times, v1→h2 once. The true route is v2→h3→h1; the method skipped the middle tank.

Common ancestor: h1–h2, both downstream of the disturbance d through different upper tanks.

Why conditioning does not fully remove them: the levels respond to the pump's history over 60–90 s through a √h outflow, so a linear regression on 20 lagged copies of v1 leaves a residual the two siblings still share. The likely cause, not tested here.

Beyond linear-Gaussian data · 2 of 4

For non-Gaussian or nonlinear data, swap the independence test inside PCMCI+; the algorithm stays the same

Every test answers the same question, X ⊥ Y | S, with a different statistic. Cost rises as assumptions fall.

ParCorr

ρ(rₓ, rᵧ), residuals of linear fits on S

Linear, Gaussian. Fastest. Used in this deck.

1.5 s per dataset

RobustParCorr

ParCorr on rank-transformed (Gaussianised) data

Linear in rank, any marginal. Heavy tails, skew, outliers. Same speed.

~ seconds

GPDC

Gaussian-process fit on S, distance correlation of residuals

Nonlinear, additive noise. Smooth saturations, √h outflows. Available in our runner.

minutes

CMIknn

I(X; Y | S) from k-nearest-neighbour estimates, shuffle-test p-value

No assumptions at all. Needs many rows; 500 shuffles per test.

~67 min per dataset (est.)

Our runner already exposes this as a flag (parcorr, gpdc, cmiknn). The CMIknn comparison was configured on 27 September 2026 but has not been run: at 0.4 s per test and ~1000 lagged pairs, that is the 2.7 h in Next steps.

Source: datasets/run_algorithms.py (--independence-test); Plan.md runtime estimate (UNVERIFIED, extrapolated from 49 tests per lag at 0.4 s)

Beyond linear-Gaussian data · 3 of 4

The usual pre-processing fixes make the data look Gaussian but destroy the structure the tests rely on

Log, Box-Cox, quantile transforms

y = a·x + e  →  log y ≠ a'·log x + e'

A nonlinear transform of each variable turns a linear causal relation into a nonlinear one. ParCorr then reports a partial dependence that is an artefact of the transform, or misses a real one. The marginals look Gaussian; the joint no longer fits the model.

Differencing, detrending with short filters

Δhₜ = hₜ − hₜ₋₁

The drainage links live in the slow part of the signal (time constants 23–91 s). Differencing at 5 s whitens exactly that band, so the hardest true edges get weaker while high-frequency noise is amplified. Our series are already stationary; there is nothing to remove.

Clipping or winsorising outliers

x ← min(max(x, q₀.₀₁), q₀.₉₉)

The extreme samples are the informative ones for direction: LiNGAM's identifiability comes entirely from non-Gaussian tails. Trimming them removes the signal it needs and biases the VAR fit near the bounds.

✓

What is safe: standardising (z-scoring) each column, because it is linear; removing burn-in; keeping all inputs in the data so no confounder is hidden. Everything else should be handled by choosing the test, not by reshaping the data.

Source: reasoning from the model assumptions on the previous slide; no transform experiment was run on this benchmark

Lagged variables turn feedback loops into an acyclic graph, as long as the loop is slower than the sampling interval

Aₜ₋₁ → Bₜ and Bₜ₋₁ → Aₜ are two different edges in the lagged graph. Neither can point backwards in time, so the cycle disappears and the collider rules are never needed for lagged links.

Condition: the loop's round-trip time must be longer than the sampling interval Ts, otherwise both directions collapse into the same-time slice and the cycle returns.

Here: Ts = 5 s, tank time constants 23–91 s

5 to 18 samples per loop

Seen in the results: the tanks' self-loops hᵢ(t−1) → hᵢ(t) are the one cycle this rig has. PCMCI+ reported all 7 self-dependencies (levels and inputs) in both datasets; windowed PC found 6 to 7. The same mechanism will handle recycle streams and control loops on a plant.
