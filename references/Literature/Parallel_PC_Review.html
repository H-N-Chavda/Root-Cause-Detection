Parallel-PC: a technical review

Le, Hoang, Li, Liu, Liu & Hu, “A fast PC algorithm for high dimensional causal discovery with multi-core PCs”. arXiv:1502.02454 (v1 Feb 2015, v3 Nov 2016); IEEE/ACM Trans. Comput. Biol. Bioinform. 16(5), 2019, doi:10.1109/TCBB.2016.2591526. Review prepared 18 Nov 2026.

Verdict

The method is theoretically sound, but it does not offer a different estimator. Parallel-PC is PC-stable (Colombo & Maathuis, 2014) with the conditional-independence (CI) tests of each level spread across CPU cores. Given the same data, CI test, α and variable order, it returns the same skeleton and the same separating sets as PC-stable, so it gives the same CPDAG. The only gain is speed: the paper reports 3–6× on 8 cores and at most about 12.7× on 14 cores. There is no change in accuracy relative to PC-stable. The accuracy gain the paper reports over the original PC comes from PC-stable's order-independence, not from parallelism.

It is not worth adopting as a separate tool. The reference R package was last released in 2015 and was archived from CRAN in December 2025. A single-threaded C++ PC-stable (pcalg's stable.fast) roughly matches the 8-core R Parallel-PC. GPU implementations (cuPC) are faster by two to three orders of magnitude. The level-synchronous parallelisation scheme itself is the lasting contribution, and modern tools already use it. If PC-stable is too slow for you, use a compiled PC-stable (multi-threaded where available) or cuPC for Gaussian data. Do not install ParallelPC.

1. Mathematical foundations: PC and PC-stable

1.1 Assumptions

Parallel-PC uses the standard PC assumptions Paper §3.1 and adds none of its own. Let \(G=(V,E)\) be a DAG over \(p=|V|\) variables with joint distribution \(P\).

  • Causal Markov condition: every \(X\) is independent of its non-descendants given its parents, \(X \perp\!\!\!\perp \mathrm{ND}(X)\mid \mathrm{Pa}(X)\).
  • Faithfulness: \(X \perp\!\!\!\perp Y \mid S\) in \(P\) only if \(X\) and \(Y\) are d-separated by \(S\) in \(G\).
  • Causal sufficiency: there are no unobserved common causes.
  • The CI test is chosen to suit the data: Fisher-z partial correlation for Gaussian data, G² or χ² for discrete data, or kernel tests.

1.2 Adjacency criterion

The skeleton phase rests on one lemma (Spirtes et al., 2000; Theorem 1 in the paper):

\[ X,Y \text{ non-adjacent in } G \;\Longrightarrow\; \exists\, S \subseteq \mathrm{adj}(X,G)\setminus\{Y\} \ \text{ or } \ S \subseteq \mathrm{adj}(Y,G)\setminus\{X\} \ \text{ such that } X \perp\!\!\!\perp_G Y \mid S . \]

PC searches for such an \(S\) in order of increasing size \(\ell = |S| = 0,1,2,\dots\) (the “level” or “depth”). It looks only inside the current estimated adjacency sets, which shrink as edges are removed. That pruning is why PC is fast on sparse graphs.

1.3 The CI test (Gaussian case)

Every implementation discussed here, including the paper's experiments, cuPC and our test harness, uses the Fisher-z test on the sample partial correlation:

\[ \hat\rho_{XY\cdot S} = -\frac{\Omega_{12}}{\sqrt{\Omega_{11}\Omega_{22}}},\quad \Omega = \big(\hat\Sigma_{\{X,Y\}\cup S}\big)^{-1},\qquad Z = \tfrac12\log\frac{1+\hat\rho}{1-\hat\rho}, \]
\[ \text{declare } X \perp\!\!\!\perp Y\mid S \iff \sqrt{n-|S|-3}\;|Z| \le \Phi^{-1}(1-\alpha/2)\quad(\text{equivalently } p\text{-value}\ge\alpha). \]

One test costs \(O(|S|^3)\) once the \(p\times p\) correlation matrix has been computed, which takes \(O(np^2)\). A Fisher-z test therefore takes microseconds, while a kernel test (KCI) costs \(O(n^3)\). This difference in test granularity largely decides whether parallelising pays off (§5).

1.4 Original PC versus PC-stable

Original PC (Spirtes et al., 2000)
  1. G ← complete graph; ℓ ← 0
  2. repeat
  3.  for each ordered pair (X,Y) adjacent in G:
  4.   for S ⊆ adj(X,G)\{Y}, |S|=ℓ:
  5.    if X ⊥ Y | S: delete X–Y now;
  6.     sepset(X,Y) ← S; break
  7.  ℓ ← ℓ+1
  8. until every |adj(X,G)\{Y}| < ℓ

Adjacency sets are live, so a deletion immediately shrinks the conditioning candidates of later pairs. The result depends on the order of the variables.

PC-stable (Colombo & Maathuis, 2014)
  1. G ← complete graph; ℓ ← 0
  2. repeat
  3.  a(X) ← adj(X,G) for all X  (frozen)
  4.  for each ordered pair (X,Y) adjacent in G:
  5.   for S ⊆ a(X)\{Y}, |S|=ℓ:
  6.    if X ⊥ Y | S: delete X–Y;
  7.     sepset(X,Y) ← S; break
  8.  ℓ ← ℓ+1
  9. until every |a(X)\{Y}| < ℓ

Within a level, deletions do not change anyone's conditioning candidates. The skeleton is order-independent, at the cost of more CI tests.

Formally, PC-stable at level \(\ell\) computes

\[ E_{\ell+1} = \Big\{\{X,Y\}\in E_\ell \;:\; \nexists\, S \in \tbinom{a_\ell(X)\setminus\{Y\}}{\ell} \cup \tbinom{a_\ell(Y)\setminus\{X\}}{\ell} \text{ with } \hat I(X,Y\mid S)=1\Big\},\qquad a_\ell(\cdot)=\mathrm{adj}(\cdot,\,(V,E_\ell)). \]

Here \(\binom{A}{\ell}\) is the set of all size-\(\ell\) subsets of \(A\) and \(\hat I\) is the test decision. For each edge, whether it survives depends only on \(E_\ell\) and the data, not on the outcome of any other edge's tests at the same level. Order-independence comes from this, and so does the ability to run the tests in parallel Inference. Parallel-PC is built on exactly this property.

2. What Parallel-PC changes

Paper §4.2, Alg. 2 Parallel-PC keeps PC-stable's mathematics unchanged and only changes how one level is executed. Each level is split into three stages:

  1. Distribute: after the adjacency sets \(a_\ell(\cdot)\) are frozen, the set \(J\) of unordered adjacent pairs is split evenly (by count) into \(P\) groups \(J_1,\dots,J_P\), one per core.
  2. Test in parallel: each core processes its edges independently. For edge \(\{X,Y\}\) it searches \(S\subseteq a(X)\setminus\{Y\}\) and then, only if no separating set was found, \(S\subseteq a(Y)\setminus\{X\}\). It records a keep/delete flag \(k_{XY}\) and the first separating set found.
  3. Synchronise: a barrier waits for all cores, then every edge with \(k_{XY}=\text{FALSE}\) is deleted from \(G\) and its sepset is stored. Then \(\ell\leftarrow \ell+1\).

Two engineering details:

  • Edge grouping. Both directions of an edge, \((X,Y)\) and \((Y,X)\), stay on the same core. If the \(X\)-side search succeeds, the \(Y\)-side tests are skipped. Sending the two sides to different cores would waste those tests. pcalg's sequential PC-stable already behaves this way, because it skips \((Y,X)\) once the edge is gone, so grouping preserves its test count. Inference from source
  • Memory-efficient mode (mem.efficient=TRUE). The edge list of a level is processed in batches of \(t_b\) edges, where \(t_b\) is estimated from free RAM as about 2 MB per edge task in the R code. Each batch has its own barrier. The paper reports that peak memory roughly halves at a small time cost (Table 2). In the R implementation the adjacency snapshot is taken once per level, before batching, so batching does not affect the output Inference from source.

2.1 What is not parallelised

  • Levels run strictly one after another. Level \(\ell+1\) needs \(E_{\ell+1}\) before it can start, so there is one barrier per level and \(q+1\) barriers in total, where \(q\) is the largest adjacency size reached.
  • Tests within one edge run one after another. They have to, so that the early stop and the “first separating set found” rule behave as in PC-stable. cuPC later relaxed this (§5.4).
  • Orientation (v-structures, then Meek's rules R1–R3) and the extra CI tests needed for the conservative and majority-rule variants run sequentially. Paper §3.2 says the skeleton phase dominates the cost, and that is usually true.

3. Worked example: why the three variants agree or disagree

The setting follows the paper's Figure 1. There are four variables \(A,B,C,D\). After level 0 the graph has edges \(A\!-\!B,\ A\!-\!C,\ A\!-\!D\) and \(B\!-\!C\). At level 1, suppose the finite-sample tests return:

\[\hat I(A,B\mid C)=1,\qquad \hat I(A,C\mid B)=1,\qquad \text{every other level-1 test } =0 .\]

Both results cannot be right together. Each one alone justifies removing an edge, but at least one of them is a test error. This is the usual situation when \(n\) is small.

3.1 Where order dependence remains: separating sets and v-structures

Suppose \(X - Z - Y\) is an unshielded triple, and at level 1 both \(\hat I(X,Y\mid Z)=1\) and \(\hat I(X,Y\mid W)=1\) hold for some other neighbour \(W\). PC-stable, and therefore Parallel-PC, stores the first separating set it finds. Subsets are enumerated in the order of the variable indices.

\[ \text{sepset}=\{W\} \Rightarrow Z\notin\text{sepset} \Rightarrow X\to Z\leftarrow Y \qquad\text{vs.}\qquad \text{sepset}=\{Z\} \Rightarrow \text{no v-structure.} \]

Renaming the variables can swap which set comes first. That can change the CPDAG even though the skeleton stays the same. Colombo & Maathuis (2014) prove that PC-stable makes only the skeleton order-independent. To make v-structures order-independent they propose CPC (conservative: check every separating set) and MPC (majority rule). solve.confl handles conflicting orientations. Follow-up The paper's statement that Parallel-PC's “results … [are] independent of the variable ordering” is therefore true of the skeleton only, unless the conservative or majority-rule option is used. Colombo & Maathuis In our run (§8), the PC-stable sepsets differed across all 10 orderings, but in that instance the v-structures did not. The risk is real, but it is not triggered on every dataset.

4. Graph equivalence

4.1 What can be proved

Proposition (exact equivalence with PC-stable). Fix the data, a deterministic CI test, α, m.max and the variable labelling. Within each edge, search \(a(X)\) first and then \(a(Y)\), both in lexicographic subset order. Then for any number of cores \(P\) and any assignment of edges to cores, Parallel-PC returns the same \(E_\ell\) at every level, the same sepsets, and therefore the same CPDAG as sequential PC-stable.

Proof sketch. Use induction on \(\ell\). Assume \(E_\ell\) is equal in both. Then the frozen \(a_\ell(\cdot)\) are equal. Edge \(e\)'s test sequence is a function of \((e, a_\ell, \text{data})\) only, so its keep/delete decision and its first separating set are equal. The synchronisation step applies the union of the deletions, which is the same set in both. So \(E_{\ell+1}\) is equal. The orientation phase is a deterministic function of (skeleton, sepsets), so its output is equal too. ∎ Inference

The paper states equivalence (“generates the same output … compared to that of the stable-PC algorithm”, §5.2 and §7) and argues for it informally (§4.2: tests at a level “are independent of each other”). It does not give a formal proof. Paper I checked the archived R source (ParallelPC_1.2, skeleton_parallel). Its per-edge function follows pcalg's R-level skeleton(method="stable") exactly: it enumerates pairs \(x<y\), searches the \(x\)-side then the \(y\)-side with getNextSet order, and stores sepset[[x]][[y]] or sepset[[y]][[x]]. So the proposition applies to the actual software. Inference from source Tested

5. Computational analysis

5.1 Where the time goes

Kalisch & Bühlmann (2007) bound the number of CI tests PC performs when the true graph has maximum degree \(q\):

\[ \#\text{tests} \;\le\; 2\binom{p}{2}\sum_{i=0}^{q}\binom{p-1}{i} \;\le\; \frac{p^{2}(p-1)^{q}}{(q-1)!}. \]

This is polynomial in \(p\) for fixed \(q\) and exponential in \(q\). PC-stable has the same worst case but runs more tests in practice, because adjacency sets shrink only between levels. Paper §3.3 Write \(w_e^{(\ell)}\) for the cost of all tests on edge \(e\) at level \(\ell\). Then

\[ T_{\text{seq}} = \sum_{\ell=0}^{q}\sum_{e\in E_\ell} w_e^{(\ell)},\qquad w_e^{(\ell)} \le \Big[\tbinom{|a(X)|-1}{\ell}+\tbinom{|a(Y)|-1}{\ell}\Big]\,\tau(\ell,n), \]

where \(\tau\) is the cost of one test. Parallel-PC changes the constant and leaves the growth rate alone:

\[ T_{\text{par}}(P) = \sum_{\ell=0}^{q}\Big[\max_{1\le k\le P}\ \sum_{e\in J_{\ell,k}} w_e^{(\ell)} \;+\; O_\ell(P)\Big], \qquad S(P)=\frac{T_{\text{seq}}}{T_{\text{par}}(P)} \;\le\; \min\!\Big(P,\ \frac{\sum_\ell W_\ell}{\sum_\ell \max\big(W_\ell/P,\ \max_e w_e^{(\ell)}\big)}\Big), \]

with \(W_\ell=\sum_e w_e^{(\ell)}\) and \(O_\ell(P)\) the cost of forking, serialising and synchronising. Inference This model leads to three conclusions:

  • Exponential worst case unchanged. At best the time is divided by \(P\). A problem that is infeasible because \(q\) is large stays infeasible.
  • Straggler bound. Work per edge is very skewed, since \(\binom{|a(X)|-1}{\ell}\) grows quickly for hub nodes. A single hub edge at a high level can take longer than all the other work combined, which caps the speedup whatever \(P\) is. Splitting edges evenly by count (static scheduling) makes this worse. The authors acknowledge this and list cost-aware scheduling as future work. Paper §7
  • Granularity. Parallelism pays off only if \(W_\ell/P \gg O_\ell(P)\). A Fisher-z test takes a few microseconds, so small problems run slower in parallel (see §8). Expensive tests such as KCI, or G² on large \(n\), benefit the most.

5.3 Memory

  • Sequential PC-stable: \(O(p^2)\) for the correlation matrix and adjacency matrix, plus \(O(p^2)\) sepset slots.
  • Parallel-PC on Linux/macOS uses mclapply (fork, copy-on-write). Shared data is not copied up front, but every worker builds result lists, and R's garbage collector touching pages forces copies. The paper's Table 2 measures peak memory of 0.9–4 GB without the memory-efficient option and about half that with it. S. cerevisiae (p = 5361) ran out of memory (more than 8 GB) without it. Paper Table 2
  • Windows uses a PSOCK cluster, which sends a full copy of the data to each worker: \(O(P\cdot p^2)\). Inference from source
  • The memory-efficient mode cuts peak memory by adding more barriers (one per batch). Its batch size comes from a hard-coded estimate of 2 MB per edge task.

7. Why Parallel-PC is under-used

7.1 Evidence-backed explanations

  1. The reference software is no longer maintained. CRAN ParallelPC had releases 1.0 (Oct 2015), 1.1 (Oct 2015) and 1.2 (31 Dec 2015) and none since. CRAN archived it on 17 Dec 2025 because “issues were not corrected in time”. It cannot be installed with install.packages(). CRAN archive
  2. Mainstream libraries absorbed the idea. pcalg has a compiled order-independent skeleton (method="stable.fast") with a numCores argument that uses OpenMP at the edge level, which is the same parallelisation scheme. Tetrad parallelises PC's adjacency search, “especially if the ‘stable’ option is selected” (Tetrad FAQ). bnlearn's pc.stable takes a cluster (Scutari 2017). Once PC-stable is available in these tools, a separate package adds nothing.
  3. Compiled serial code matches it, and GPUs make it look obsolete. The cuPC paper reports serial C++ stable.fast taking about the same time on DREAM5 as 8-core Parallel-PC, and cuPC being hundreds to thousands of times faster than serial C++. Zarebavani et al. 2020
  4. The speedup is modest and limited. 3–6× on 8 cores, at most 12.7×, and with sublinear efficiency (§5.2). The underlying exponential dependence on \(q\) does not change.
  5. The contribution is incremental. Once PC-stable freezes adjacency sets per level (Colombo & Maathuis, arXiv 2012), parallelising within a level is the obvious next step. Madsen et al. (2015; KBS 2017) independently parallelised PC's CI tests in the same period. That makes the paper's claim to be “the first work of utilising parallel computing for the PC algorithm” hard to rely on.

7.2 Plausible but unverified explanations Inference

  • Competition from other algorithm families. At scale, practitioners often choose FGES (Ramsey et al. 2017; about 10⁶ variables), continuous optimisation (NOTEARS and its successors), or local Markov-blanket methods instead of faster PC.
  • Visibility. The paper appeared in a bioinformatics venue, and the journal version was published in 2019, more than three years after the arXiv preprint. It reached the causal-discovery methods community less directly.
  • “Parallel-PC” is an implementation strategy, not an estimator. Methods papers cite and compare estimators (PC, PC-stable, CPC). An implementation that produces the same graph has no statistical result of its own to cite.

9. Recommendations

QuestionAnswer
Theoretically sound?Yes. It computes the PC-stable estimator exactly and inherits PC-stable's consistency and order-independence of the skeleton.
Same CPDAG as standard PC?With oracle tests, yes. With finite samples, it matches PC-stable, not original PC. The CPDAG can still change with variable order unless CPC or majority rule is used.
Worthwhile in practice?Only as a scheme, not as the ParallelPC package. Use a compiled PC-stable first. Add edge-level parallelism when CI tests are expensive (kernel tests, large n). Use cuPC when the data are Gaussian and \(p\) is in the thousands.
For this project (PC on drum PCA components)The problem is small (tens of variables), so a parallel PC would be overhead-bound, as in our p = 120 test. Use stable=True (causal-learn) or stable.fast + maj.rule (pcalg) to get order-independent results. Parallelism is not needed. Inference
